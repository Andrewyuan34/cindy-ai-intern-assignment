# 我的 PR 看板 · B1 最小版本

Cindy 常驻右侧面板，提供“我创建的”和“待我评审”两个未关闭 PR 列表。打开面板、返回前台或点击刷新时读取 GitHub；没有定时轮询，也没有 GitHub webhook 或接收服务。

每项显示仓库、PR 标题、草稿标记与最新 head SHA 的 CI 状态。展开状态可看检查项，点击“分析 CI”把最新 PR、失败检查注释和 Actions 步骤摘要交给独立 Cindy 任务；“查看诊断”直接打开该任务，“重新分析”继续使用同一 GitHub 账号、同一 PR 的原任务。

## 连接与使用

1. 使用 **Cindy 0.1.126 或更新版本**。通过 Cindy Forge 的 `ghost_forge_pack` 打包，再用 `ghost_forge_install` 安装，按 Cindy 原生提示批准声明的网络与任务能力。更新时更新原插件实例，保留宿主中的 PR→任务关联。
2. 优先复用此电脑的 gh 登录；可在 Cindy 提供的登录入口连接，或在本机运行 `gh auth login`。没有可用 gh 登录时，在插件设置中保存备用 PAT；无需把 token 交给聊天。
3. 首次使用时进入任意 Cindy 任务，展开右侧栏，选择“我的 PR”页签。切换“我创建的”和“待我评审”列表；每页 20 条，存在后续结果时可“加载更多”。
4. 点击“分析 CI”创建独立诊断任务。出现“查看诊断”后点击即可原生切换到该任务，右侧任务页显示对应 PR；在主对话中查看结果或继续提问。再次诊断使用“重新分析”。
5. 模型、权限和工作环境沿用 Cindy 插件任务设置；插件未指定额外权限覆盖。工具需要批准时，在 Cindy 原生授权界面处理，插件不会代替用户批准或自动提权。点击 PR 链接时，按 Cindy 外链提示确认后在浏览器查看。

凭据由宿主保险库保存，仅注入 `api.github.com` 请求。PAT 应有目标仓库的 Pull requests、Checks、Commit statuses、Actions 读取权限；组织 SSO 与仓库授权仍以 GitHub 为准。插件不修改 PR、不重新运行 CI、不自动改代码，也不会因刷新启动模型。

诊断提示词优先引导 AI 使用本插件的 `get_pr_ci` 获取当前 PR 的检查与失败证据，再按需要读取相关测试或源码。检查与日志属于外部资料，不作为执行指令。

## 当前验证状态

当前交付源码为 **0.1.2**，本地 61 项测试再次通过。完整实机闭环在 **0.1.1 / Cindy 0.1.126** 上完成：真实失败 CI、AI 定位原因、修复后 4 项 CI 测试通过、看板绿灯，以及在同一诊断任务中重新分析并确认修复；原生任务导航和 PR 外链也已验证。

0.1.2 仅补充诊断提示词的证据边界：成功检查未采集注释不代表缺陷，当前无检查不代表历史从未运行，CI 状态不等同于分支保护结论。权限不足、运行中状态等由本地测试覆盖；备用 PAT 保存流程未使用真实凭据演练，未声称所有账号与情形均已实测。证据见 [IMPLEMENTATION.md](IMPLEMENTATION.md)。

## 本地检查

需要 Node 22；没有 npm 依赖，无需安装整个 Cindy 项目的依赖。

```powershell
node --test tests/*.test.mjs
node dev/preview.mjs
```

预览地址：`http://127.0.0.1:4318`。页面顶部明确标注演示数据；模拟 GitHub、Cindy 任务和 KV，不发真实模型请求，设置预览拒绝保存凭据。

可选的真实只读 API 检查：

```powershell
node dev/live-smoke.mjs
```

此脚本通过已登录的 gh 验证同一个数据模块，不读取 token，不代表 Cindy 宿主联调通过。

## 边界

- 界面事件刷新不是远端 GitHub 推送。面板一直保持前台时，需要手动刷新才能看到新的变化；30 秒内重复前台事件合并，手动刷新不受该间隔限制。
- CI 指当前 PR 的最新 head SHA 检查与提交状态，不等同于满足分支保护或 merge commit 的全部要求。没有检查、权限不足、响应截断、未读完的检查页都不会标成通过。
- GitHub 搜索最多返回 1,000 条。结果不完整会显示提示。CI 每端点先取 100 条；诊断最多获取 6 个失败检查的注释、4 个失败工作流的 jobs/steps，超限会标记资料不完整。不会下载 Actions ZIP 日志。
- PR→任务关联按 GitHub 账号隔离，存于宿主 `/kv`；持久化失败则停止派发。未知发送结果会保留原请求键和完整参数以供重试，不换键重复发送。
- 任务接口不可用或授权不足时，列表仍可使用。任务被删除或归档后会提示用户处理，不偷偷创建替代任务。
- 最低版本为 Cindy 0.1.126，已在该版本完成含任务导航的整包安装与真实点击验证。任务 API 仍标记 experimental，运行时继续检查能力；“查看诊断”需要用户当次点击，点击过期时提示重试，不自动反复导航。

## 文件

| 文件 | 用途 |
|---|---|
| `ghost.json` | 身份、常驻面板、任务页、GitHub 凭据与任务能力声明 |
| `main.js` | 宿主桥接、请求去重、AI 可调用的只读工具 |
| `lib/github.mjs` | GitHub 查询、CI 合并、诊断资料收集 |
| `lib/controller.mjs` | 刷新、分页、账号切换、任务导航与界面状态 |
| `lib/tasks.mjs` | 每 PR 独立任务、持久化幂等请求与恢复 |
| `lib/store.mjs` | 64 KiB KV 内的串行整对象写入 |
| `panel.*` / `settings.*` | 面板与安全凭据设置 |
| `task.html` / `task.js` | 独立诊断任务的 PR 上下文页，不额外调用模型 |
| `tests/` / `dev/` | 行为测试、演示宿主和可选只读烟测 |

验证记录与实施说明见 [IMPLEMENTATION.md](IMPLEMENTATION.md)。
